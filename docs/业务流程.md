# 业务流程

## 门诊闭环

```mermaid
flowchart LR
  A[患者建档或注册] --> B[选择医生并挂号]
  B --> C[WAITING 待接诊]
  C --> D[医生开始接诊]
  D --> E[IN_PROGRESS 接诊中]
  E --> F[保存病历并开处方]
  F --> G[COMPLETED 挂号完成]
  F --> H[UNPAID 待缴费]
  H --> I[线上支付或现金确认]
  I --> J[PAID 已缴费]
  J --> K[药房发药]
  K --> L[DISPENSED 已发药]
  L --> M[患者确认取药]
  M --> N[PICKED_UP 已取药]
```

## 挂号状态

```mermaid
stateDiagram-v2
  [*] --> WAITING: 创建挂号
  WAITING --> IN_PROGRESS: 医生开始接诊
  WAITING --> CANCELLED: 管理员或患者取消
  IN_PROGRESS --> COMPLETED: 提交处方后自动完成
```

| 状态          | 含义     | 下一步             |
| ------------- | -------- | ------------------ |
| `WAITING`     | 等待接诊 | 开始接诊；取消     |
| `IN_PROGRESS` | 正在诊疗 | 保存病历；开具处方 |
| `COMPLETED`   | 接诊结束 | 查询历史           |
| `CANCELLED`   | 挂号取消 | 无                 |

同一患者、同一医生、同一天不能重复创建未取消号源；医生必须启用。

## 医生接诊与处方

1. 医生登录后，系统从会话的 `doctorId` 加载本人待诊队列。
2. 仅 `WAITING` 挂号可开始接诊，状态改为 `IN_PROGRESS`。
3. 医生只可读取或保存本人挂号的病历。
4. 仅接诊中的挂号可开处方；服务端校验药品数量和单价。
5. 服务端计算明细金额和处方总额，写入处方与明细后自动完成挂号。

## 处方状态

```mermaid
stateDiagram-v2
  [*] --> UNPAID: 医生提交处方
  UNPAID --> PAID: 患者支付 / 管理员现金确认
  UNPAID --> CANCELLED: 管理员作废
  PAID --> DISPENSED: 药房发药
  DISPENSED --> PICKED_UP: 患者确认取药
```

| 状态                      | 含义     | 谁可操作                                     |
| ------------------------- | -------- | -------------------------------------------- |
| `UNPAID`                  | 待缴费   | 患者支付；未注册患者可现金确认；管理员可作废 |
| `PAID`                    | 等待药房 | 药房发药                                     |
| `DISPENSED`               | 已发药   | 对应患者确认取药                             |
| `PICKED_UP` / `CANCELLED` | 已结束   | 无                                           |

发药会创建取药通知；确认取药会同步将该处方关联通知标记为已读。

## 并发与权限保护

- 状态更新带旧状态条件，重复点击时只有一个请求能成功。
- 患者端校验当前 `patientId` 是否拥有该挂号或处方。
- 医生端校验当前 `doctorId` 是否拥有该挂号。
- 已注册患者不能由管理员代为现金确认，避免绕过患者端支付。
