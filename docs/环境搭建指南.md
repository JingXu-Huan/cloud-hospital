# 云医院门诊闭环：环境搭建指南

本文以 Windows 11 + PowerShell 7 为例，说明如何在本机启动完整的前后端与 MySQL 环境。

## 1. 技术栈与前置条件

| 组件           | 用途                  | 要求                          |
| -------------- | --------------------- | ----------------------------- |
| Git            | 获取代码              | 任意近期版本                  |
| JDK            | 运行 Spring Boot 后端 | **Java 17**                   |
| Maven          | 构建、启动后端        | Maven 3.9+                    |
| Node.js        | 安装、运行 Vue 前端   | Node.js 20 LTS（含 npm）      |
| Docker Desktop | 运行项目 MySQL        | 已启动，Linux containers 模式 |

项目包含以下服务：

- `hospital-server`：Spring Boot 3.3.5，默认监听 `http://localhost:8080`。
- `hospital-web`：Vue 3 + Vite，默认监听 `http://localhost:5173`。
- MySQL 8.4：由根目录 `compose.yaml` 提供，宿主机端口为 `3306`。

> 项目没有 Maven Wrapper（`mvnw`），因此需要在系统中安装 Maven，并确保 `mvn` 可在 PowerShell 中运行。

## 2. 安装与检查基础工具

安装 JDK、Maven、Node.js 和 Docker Desktop 后，重新打开 PowerShell，在项目根目录运行：

```powershell
java -version
mvn -version
node --version
npm --version
docker version
docker compose version
```

验收标准：

- `java -version` 显示 17.x；不要用 JDK 8 或 JDK 11。
- `mvn -version` 中的 Java home 指向 JDK 17。
- `docker version` 同时显示 Client 与 Server；若只有 Client，先启动 Docker Desktop。

若 `mvn` 或 `java` 无法识别，请检查系统环境变量：`JAVA_HOME` 应指向 JDK 17 安装目录，`Path` 应包含 `%JAVA_HOME%\bin` 和 Maven 的 `bin` 目录。Node.js 安装后通常无需手工配置。

## 3. 获取并进入项目

如果尚未有代码，先克隆仓库；已有项目则直接进入根目录：

```powershell
git clone <仓库地址> cloud-hospital
Set-Location cloud-hospital
```

后续命令均假定当前目录为包含 `compose.yaml`、`hospital-server`、`hospital-web` 和 `sql` 的项目根目录。

## 4. 启动数据库

### 4.1 使用 Docker（推荐）

```powershell
docker compose up -d mysql
docker compose ps
docker compose logs mysql --tail 50
```

当 `docker compose ps` 中 `mysql` 为 `running (healthy)` 时，数据库即可使用。首次创建数据卷时，容器会依次执行：

1. `sql/init.sql`：创建全部业务、账号和患者通知表并导入演示数据。

默认连接信息如下：

| 配置项   | 值               |
| -------- | ---------------- |
| Host     | `127.0.0.1`      |
| Port     | `3306`           |
| Database | `cloud_hospital` |
| Username | `root`           |
| Password | `root`           |

可用下面的命令确认初始化结果：

```powershell
docker compose exec mysql mysql -uroot -proot -e "USE cloud_hospital; SHOW TABLES;"
```

### 4.2 不使用 Docker 时

可以使用已安装的 MySQL 8.0/8.4，但需手动创建数据库与导入脚本：

```powershell
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS cloud_hospital CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
Get-Content -LiteralPath 'sql/init.sql' | mysql -uroot -p cloud_hospital
```

然后按实际账户设置后端环境变量。当前 PowerShell 窗口可这样设置：

```powershell
$env:DB_HOST = '127.0.0.1'
$env:DB_PORT = '3306'
$env:DB_NAME = 'cloud_hospital'
$env:DB_USER = '<你的用户名>'
$env:DB_PASSWORD = '<你的密码>'
```

这些变量仅对当前终端有效。启动后端的终端需要保留它们。

## 5. 启动后端

打开一个 PowerShell 窗口：

```powershell
Set-Location hospital-server
mvn spring-boot:run
```

后端默认使用 `hospital-server/src/main/resources/application.yml` 中的配置，并允许以下环境变量覆盖：

| 环境变量      | 默认值           | 说明           |
| ------------- | ---------------- | -------------- |
| `SERVER_PORT` | `8080`           | 后端 HTTP 端口 |
| `DB_HOST`     | `127.0.0.1`      | MySQL 主机     |
| `DB_PORT`     | `3306`           | MySQL 端口     |
| `DB_NAME`     | `cloud_hospital` | 数据库名       |
| `DB_USER`     | `root`           | 数据库账户     |
| `DB_PASSWORD` | `root`           | 数据库密码     |

出现类似 `Started HospitalApplication` 的日志，说明后端启动成功。随后可验证接口：

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/auth/login -Method Post -ContentType 'application/json' -Body '{"username":"admin","password":"admin123"}'
```

如果要仅做编译检查：

```powershell
mvn clean package
```

## 6. 启动前端

另开一个 PowerShell 窗口，在项目根目录执行：

```powershell
Set-Location hospital-web
npm install
npm run dev
```

打开命令行输出的地址，通常为 `http://localhost:5173`。前端会将以 `/api` 开头的请求代理给 `http://localhost:8080`，所以启动前端前应确保后端已运行。

如需验证前端生产构建：

```powershell
npm run build
```

构建产物输出到 `hospital-web/dist`。

## 7. 一次完整验收

按照下列顺序操作，能够避免前端因后端或数据库尚未就绪而报错：

1. 在根目录运行 `docker compose up -d mysql`，确认状态为 `healthy`。
2. 在第一个终端运行 `Set-Location hospital-server` 和 `mvn spring-boot:run`。
3. 调用登录接口，确认返回会话 JSON。
4. 在第二个终端运行 `Set-Location hospital-web`、`npm install`、`npm run dev`。
5. 打开 `http://localhost:5173`，验证管理员端的挂号、医生接诊、收费订单、药房，以及患者端的自助挂号和订单支付流程。

## 8. 常见问题

### 3306 端口被占用

先检查端口占用：

```powershell
Get-NetTCPConnection -LocalPort 3306 -ErrorAction SilentlyContinue
```

关闭占用该端口的本地 MySQL，或修改 `compose.yaml` 的端口映射，例如改为 `"3307:3306"`，同时在启动后端的终端设置 `$env:DB_PORT = '3307'`。

### 数据库没有重新导入演示数据

MySQL 初始化脚本只会在数据卷第一次创建时执行。若明确要清空所有本地项目数据并重新初始化，可在项目根目录执行：

```powershell
docker compose down -v
docker compose up -d mysql
```

> `down -v` 会删除本项目 MySQL 数据卷，现有数据不可恢复；只应在需要重置演示数据时使用。

### 前端页面请求失败或显示网络错误

依次确认：后端日志中已出现启动成功信息；`http://localhost:8080/api/v1/doctors` 可访问；Vite 仍运行在 `5173`；没有将前端直接打开为本地 HTML 文件。前端代理地址在 `hospital-web/vite.config.js` 中配置。

### Maven 下载依赖失败

确认网络能够访问 Maven Central，然后重试：

```powershell
Set-Location hospital-server
mvn -U clean package
```

如处于公司网络，请按网络规范配置 Maven 镜像或代理；不要把账号密码提交到项目配置文件。

## 9. 停止服务

- 前后端开发服务器：在各自终端按 `Ctrl+C`。
- 停止数据库但保留数据：`docker compose down`。
- 下次继续开发：重新执行第 4、5、6 节的启动命令即可。
